# 03 · 架构与技术选型（M0 定稿）

**上游**：[02-需求解读.md](02-需求解读.md)、[01-题目文档.md](01-题目文档.md)
**状态**：✅ M0 定稿（2026-10-15）

---

## 一、设计原则（每条都可被测试或审计）

1. **确定性**：解析与指标全部为纯函数——同一日志 → 同一 IR → 同一结论；无随机、无时钟、无 LLM；
2. **只读**：绝不写用户代码、绝不修改用户日志；只读分析；
3. **零上传**：无网络请求、无遥测；产物只落本地；
4. **口径单点**：阈值与口径定义集合只在 `config.py` 出现一次（FR-16 + AST 守门）；
5. **未核对不启用**：未经过本机实测核对的日志字段不进入计算路径（落 `unknown` 并计数）；
6. **可证伪**：指标为计数与结构性事实；基准可复现；"未启用"不冒充"通过"。

## 二、分层架构

```
用户
 └─ CLI（argparse；退出码契约；编码护栏）
     └─ 编排层 pipeline.py（run_* 函数组；CLI 只做参数解析与输出格式化）
         ├─ 发现层 discovery.py     路径自适应（参数 > 环境变量 > 默认位置）
         ├─ 解析层 parsers/         Claude Code / Codex → 统一会话 IR（唯一层间契约）
         ├─ 引擎层 engine/          返工检测 · Read:Edit 比 · 符号提取 · 粗匹配
         ├─ 报告层 report/          Markdown / HTML（零判定逻辑、零外链、纯函数）
         └─ 基准套件 benchmark/     合成会话生成（tools/）+ 植入真值 + 覆盖率门槛 + runner
横切 ─ config.py（阈值唯一口径）· exitcodes.py（退出码契约）· stdio.py（编码护栏）· selftest.py
```

**依赖方向（单向，违反即测试报红）**：
`cli → pipeline → {discovery, parsers, engine, report, benchmark}`；`parsers → ir + common`；`engine → ir + config`；`report → engine 类型 + model`；`config / exitcodes / stdio` 为叶子（不 import 业务模块）。

## 三、技术选型

| 项 | 选型 | WHY / 弃选理由 |
|---|---|---|
| 语言 | Python **≥ 3.8**（本机 3.8.8 + 3.12 双通道；CI 矩阵 3.8/3.12） | 交付"纯本地 CLI"；3.8 是系列本机底线，跨版本行为以 CI 为准 |
| 运行时依赖 | **零第三方**（仅标准库：argparse / json / re / pathlib / dataclasses / difflib） | 离线可跑、干净环境零障碍、审计面小；弃 pandas（重）、弃第三方克隆检测库（首期边界不做） |
| 相似度 | 标准库 `difflib.SequenceMatcher` + 归一化精确匹配 | 首期"粗匹配"不需要算法库；确定性不依赖第三方版本 |
| 报告 | 自写 Markdown / HTML 渲染（HTML 内联样式、零外链） | 字节确定、离线可开；弃模板引擎（重依赖） |
| 测试 | pytest（dev extra） | 事实标准；`.[dev]` 与 README/CI 同一 extras 集合（K12） |
| CI | GitHub Actions：`ubuntu-22.04×3.8` + `ubuntu-latest×3.12` + `windows-latest×3.12` | 三腿覆盖底线解释器、新解释器、Windows 编码差异（本机教训族）；未推送期间记"本地等价校验，待首推验证" |
| 打包 | `pyproject.toml`（setuptools，PEP 621）；src 布局 | 所有**被安装的包**都在 `src/` 内（防"包不在安装面"缺陷族）；`tools/` 脚本不承载被 import 的包 |
| 网络 | **不使用** | 隐私红线；CI 亦无网络步骤依赖 |

## 四、关键设计决策

| # | 决策 | WHY |
|---|---|---|
| 1 | **IR 是唯一层间契约**：双源日志先归一到统一会话 IR，下游（引擎/报告/基准）只认 IR | 双源格式差异被隔离在解析层一处；下游零格式知识，新增源不动下游 |
| 2 | **返工检测底座 = file-history 版本快照链**（本机实测存在，68 快照/9 会话） | 这是 LLM 聊天与通用静态工具都拿不到的"历史版本链"；差异化核心 |
| 3 | **粗匹配不做 AST**：归一化符号名 + difflib 高相似度，输出候选对与理由 | 01 决策：完整克隆检测工程量大且与 97★ 竞品正面撞车；粗匹配是"信号"不是"判决"（披露制） |
| 4 | **阈值/口径 config 单点**：数值与定义集合只在 `config.py`；文档/报告/生成器引用制 | 防"第二份口径"漂移；改一处全链路同变（测试断言） |
| 5 | **报告零判定逻辑**：只渲染引擎产出的模型；渲染器纯函数、**不读时钟** | 系列纪律；报告可字节复现（时间等一律作为入参传入） |
| 6 | **退出码契约先行**：0/1/2/3（+ 骨架期 4，M2 退役）锁进测试 | 脚本化用户可依赖；"阶段未就绪"绝不伪装成"无发现" |
| 7 | **编码护栏挂所有可执行入口**：`_ensure_utf8_stdio()` 按 encoding 探针决定是否 reconfigure（cp936 不动） | Windows cp1252 环境实测教训族；CP1252 复现测试常驻 |
| 8 | **合成数据纪律**：假名白名单；自研确定性 RNG（禁 stdlib random / 禁时钟）；`--check` 位级一致；冻结件禁手改 | 基准跨机器可复现的根基；零真实值入库 |
| 9 | **全部包在安装面内**：单一包 `src/agent_rework_lens/`（含 benchmark 子包） | 防"`pip install` 后 import 不到"缺陷族（README 通路 = 安装通路） |
| 10 | **内置 selftest**：版本一致性 / 口径存在性 / 退出码映射 / 编码护栏 / 发现探测 | 任何环境一条命令确认"装好了"；CI 冒烟复用 |

## 五、统一会话 IR 设计（schema v1）

**目标**：把 Claude Code jsonl 与 Codex rollout 两种完全不同的结构，归一为同一条事件流。

### 5.1 结构（`ir.py`，frozen dataclass + tuple，天然不可变）

| 类型 | 字段 | 说明 |
|---|---|---|
| `SessionMeta` | `source` / `session_id` / `cwd` / `started_at` / `source_file` / `project_slug` / `agent_version` | 会话元信息；缺失字段为 `None`（不猜测） |
| `ToolUseEvent` | `seq`（源文件行号，1 起）/ `timestamp` / `kind` / `tool_name`（原始名，保真）/ `file_path` | 归一化工具调用事件 |
| `TokenUsageEvent` | `seq` / `timestamp` / `input_tokens` / `output_tokens` / `cache_creation_input_tokens` / `cache_read_input_tokens` / `total_tokens` | 缺失计数量为 `None` |
| `ParseNote` | `code` / `message` / `count` | 解析注记（坏行计数 / 未核对字段跳过计数等），**显式可见** |
| `SessionIR` | `ir_version=1` / `meta` / `tool_events` / `token_events` / `notes` | 契约本体；`to_json()` 为 canonical（sort_keys、LF、UTF-8） |

### 5.2 `kind` 枚举与映射（映射表 = 待 M1 逐项核对的对象）

`kind ∈ {read, edit, write, multiedit, exec, other}`

| 源 | 原始工具名 | 归一 `kind` | 核对状态 |
|---|---|---|---|
| Claude | `Read` | read | ✅ 已实测存在（data/README §2.1） |
| Claude | `Edit` | edit | ✅ 已实测存在 |
| Claude | `Write` | write | ✅ 已实测存在 |
| Claude | `MultiEdit` | multiedit | ⬜ 待核对（是否存在/字段形态）→ M1 |
| Claude | `Bash` / `PowerShell` 等 | exec | ✅ 已实测存在（Bash/PowerShell 计数在册） |
| Claude | 其余工具 | other | —（保真记录 `tool_name`） |
| Codex | `exec_command` | exec | ✅ 单样本实测 |
| Codex | `apply_patch` | edit | ⚠️ 目标路径字段格式 **M1 核对**；核对前该字段不参与路径级计算 |
| Codex | `token_count` 载荷 | （token 事件） | ✅ 结构已实测 |

### 5.3 确定性约定
- 事件按 `seq`（源文件行号）排序；序列化 `json.dumps(..., sort_keys=True, ensure_ascii=False)` + 末尾 LF；
- 同一文件解析两次 → `to_json()` 逐字节一致（测试锁死）；
- 坏行只计数不中断；**解析失败 ≠ 静默跳过**（计入 `ParseNote`）。

## 七、风险与对策

| # | 风险 | 对策 |
|---|---|---|
| 1 | agent 日志格式随版本演进 | 字段核对台账（data/README）+ `unknown` 降级 + `agent_version` 记录；格式变化如实报"不支持" |
| 2 | file-history 内联信息稀疏（实测 123 行仅 11 条非空） | 版本链以 `file-history/` 目录为主源；缺失 → `insufficient_data` 显式 |
| 3 | 版本链语义未核对（v1 含义） | M1 优先核对后才启用该判定；核对前 `scan` 拦截（退出码 4） |
| 4 | Windows 编码 / 路径差异 | 编码护栏 + cp1252 复现测试；路径一律 `pathlib.expanduser`（不硬编码用户名） |
| 5 | 符号提取语言多态 | 首期仅 Python（def/class）；其他语言显式"未支持"而非猜测 |
| 6 | 口径漂移（文档/报告写第二份阈值） | config 单点 + AST 守门 + 文档引用制（K1/K12） |
| 7 | "空结果"被读成"没问题" | 空节显示"无数据"；`insufficient_data` 独立状态；未发现源明确提示不伪造报告 |
| 8 | CI 首跑集中爆缺陷（推迟建仓的已知代价） | M6 预算多轮诊断；本机双解释器 + 编码复现测试前置压力 |

## 八、规模与性能量级（本机实测快照，非承诺）

- 输入规模：Claude 会话 125 个 jsonl（KB–MB 级）+ Codex 220 个 rollout + 68 个版本快照；
- 单遍流式解析（逐行 json.loads）足够；不做索引 / 缓存 / 并发（首期）；
- 全部产物为本地小文件（报告 KB 级）。
