# 项目题：AI 代码"重复造轮子 + 返工"体检器（agent-rework-lens·会话日志级返工检测·Read:Edit 比与"新建 vs 复用"指标·合成会话基准可复现评测）

> **性质**：自拟项目题（**不参赛**，成果发布 GitHub 公开仓库）。交付形式为**纯本地 Python CLI**——扫描本机 Claude Code / Codex 会话日志，无 LLM、无 GPU、无服务器、零上传。
> **目标产出**：GitHub 公开仓库（本地目录 `10-16-agent-rework-lens`，`10-16` 为 2026-10-16 日期标签；GitHub 仓库名发布时用纯净名 `agent-rework-lens`，沿用系列惯例 `yuluo554/<kebab-name>`，署名 `yuluo554`）。
> **题目定稿日期**：2026-10-15
> **题目版本**：v1（首版定稿）
> **定位宣言**：**扫描本地 Claude Code / Codex 会话日志，回答：这次会话里 agent 有几成 Edit/Write 是在重写项目里已存在的工具函数？哪些文件被反复改回（返工）？给出可证伪的硬指标——纯本地、零模型、零上传。** 痛点有重度用户公开抱怨背书，"针对 agent 会话的重复/返工"交叉点是纯空白。
>
> **独特性拷问（AI 时代必答题）**：LLM 聊天为什么做不到？——它读不到你本机的**历史版本链**（`file-history` v1→v2→v3 覆盖快照），也没有**跨会话的持久测量基线**。本工具的两块独特性都落在"LLM 拿不到的东西"上：①**持久状态**（会话日志 + 文件版本快照 + git 历史，本地留存）；②**可复现测量基建**（确定性计数指标 + 合成会话植入真值基准，一条命令复现）。把这两点做成"聊天给不了"的体检器，而不是又一段"AI 点评代码"。

## 一、项目介绍

**痛点（有公开证据）**：重度用户对 coding agent 的两类行为有具体、可复现的抱怨——

1. **重复造轮子**：agent 倾向新建方法，而不是优雅地扩展现有方法。HN《How to improve code quality of Claude Code and codex》原话：*"agent always **duplicate and create new method instead of think about gracefully extending existing methods**...A carefully maintained claude.md imo is only a mitigation, **not a scalable solution**"*（明说现有缓解手段不 scalable = 空白）；
2. **人工评审抓不到重复与耦合**：HN《Ask HN: What tools are you using for human code review of AI-assisted code?》原话：*"AI code review tools...good at finding bugs and style nits, but **less good at finding duplicate code, module cross coupling, bad separation of concerns**"*；
3. **重构类任务直接做错**：HN《Ask HN: How are you productively using Claude code?》讨论中，agent 做"refactor duplicate code into a helper function"这类任务直接做错。

**现有开源侧的空白**：GitHub 检索（基准日 2026-10-15，7 条检索式交叉验证，见 §五 与 [data/README.md](../data/README.md)）显示——面向 agent 会话的重复/返工检测是**纯空白**：`agent duplicate code instead of refactor` → 0；`claude code rework detection` → total=1（`Cliff-AI-Lab/dev-efficiency-monitor` **1★**）；`agent created duplicate function existing util` → 0。通用重复检测的最大竞品是 `Rafaelpta/dupehound` **97★**，但它是**传统静态克隆检测**（README 明示 "No AI required"），**不面向 agent 场景**，也不看会话日志。`duplicate code detector` 检索到的 `ex_dna` 117★ / `reson` 112★ / `microsoft near-duplicate` 105★ 全是传统克隆检测。`AI generated code tech debt` 最高 11★，`vibe coding technical debt detector` 最高 3★。

**本工具的做法**：不去做又一份通用克隆检测器，而是**只做 agent 场景独有的两件事**——①**返工检测**：利用 Claude Code 的 `file-history` 版本快照链（同一文件 v1→v2→v3 被反复覆盖）与同一文件在单会话内被多次 Edit，判定"这个文件被改回去过"；②**"新建 vs 复用"指标**：统计会话内 Read:Edit 比、Write 新建的符号名与项目已有 util/符号的粗匹配，给出"这次会话有几成写操作是在重造已有的轮子"。全部指标为**确定性计数**，非模型 judgement，可证伪、可复现。

## 二、任务要求

> **首期范围限定为五个模块**（下 §1–§5）；完整 AST/指纹克隆检测、跨会话趋势、CI 集成留扩展（§6）。全部模块遵循"**未挂数据格式核对不得落库/生效**"的确定性纪律——凡解析某会话日志字段，必须先以**本机实测的真实样本**核对字段存在与语义，核对记录进 [data/README.md](../data/README.md)，未核对字段不得进入指标计算路径。
> **数值口径一处定义**：所有阈值（如"返工判定次数阈值""粗匹配相似度阈值"）只在**一处定义**（配置文件 / 常量模块），报告、基准、文档一律引用该处，**不得在多处手写第二口径**。
> **本题目不写会随实现漂移的硬数字**（测试数 / 文件数 / 体积 / 通过数）——只写指标口径与门槛来源；确需数字时以末态回填。

### 1）会话日志解析器（统一 schema 入口）

- **输入**：本机 agent 会话日志。首期支持两类源——
  - **Claude Code**：`~/.claude/projects/<project-slug>/<session-uuid>.jsonl`（本机实测 ✅ 存在，行内 `"type":"tool_use"` 含 `name` ∈ {`Edit`,`Write`,`Read`,`MultiEdit`,…}，每次 `message.usage` 含 `input_tokens`/`cache_creation_input_tokens`/`cache_read_input_tokens`/`output_tokens`）；
  - **Codex**：`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`（本机实测 ✅ 存在，行内 `session_meta`/`response_item`/`item_completed`，`token_count` 载荷含 `total_token_usage.input_tokens`/`output_tokens`/`total_tokens`）。
- **输出**：**统一中间表示**（Unified Session IR）——会话元信息（来源、session_id、cwd、时间）+ 归一化事件流（工具调用事件：`kind` ∈ {read, edit, write, multiedit, exec, other}、目标文件路径、时间戳）+ token 计量事件；
- **确定性纪律**：同一日志 → 同一 IR（纯函数、无随机、无 LLM）；**用户本地路径因机器而异，需自适应发现**（不得硬编码某个用户名下的绝对路径），发现逻辑与失败降级（找不到源 → 明确提示"未发现可分析日志"，不伪造空报告）进代码与文档；**未核对过的字段一律不解析**，解析不了的字段落 `unknown`，不得猜测补全。

### 2）返工检测引擎（确定性内核，亮点）

- **输入**：统一 IR 中的编辑事件 + `~/.claude/file-history/<session>/<hash>@vN` 版本快照链（本机实测 ✅ 存在；jsonl 内 `file-history-snapshot.trackedFileBackups` 条目含 `{"backupFileName":"<hash>@v2","version":2,"backupTime":…,"realParentDir":"…"}`）；
- **输出**：**返工文件清单**——每个文件的版本链（v1→v2→v3…）、覆盖次数、被 Edit 次数、时间跨度，以及判定标记"是否判为返工"；
- **判定口径（一处定义）**：返工判定 = 同一文件在版本链中出现 ≥N 个版本（N 在配置一处定义）**或**单会话内被 Edit ≥M 次（M 一处定义）；两个阈值都只是**可调门槛**，不是"AI 评分"；
- **确定性纪律**：返工判定是**计数与版本链的结构性事实**，不是模型 judgement；版本链缺失（无 `file-history`）时如实标 `insufficient_data`，不得据 IR 的 Edit 次数"反推"出并不存在的版本链；
- **边界**：只读分析，**不修改用户任何代码**。

### 3）Read:Edit 比与"新建 vs 复用"指标（确定性内核，亮点）

- **输入**：统一 IR 的 read/edit/write 事件 + 被写文件的**新增符号名**（从 Write/Edit 的文本载荷中确定性提取函数/类定义名）+ 项目已有符号清单（从项目源码或 `Read` 过/已存在的文件确定性提取）；
- **输出**：会话级指标——①**Read:Edit 比**（读操作 / 写操作，口径一处定义：哪些工具计入分子分母）；②**新建符号中与项目已有 util/符号"粗匹配"的比例**（"重复造轮子"信号）；
- **粗匹配口径（一处定义）**：首期只做**粗匹配**——符号名归一化（大小写/下划线连字符/常见前后缀如 `get_`/`_helper`）后的精确或高相似度匹配；**不做 AST/语义克隆检测**（见 §六 边界）；
- **确定性纪律**：匹配结果为"信号/候选"而非"判决"，报告须显式标注"粗匹配 ≠ 确认重复"，并列出匹配对与命中理由供人复核；阈值一处定义。

### 4）报告输出（本地 HTML / Markdown）

- **输入**：返工清单 + 指标结果 + 会话元信息；
- **输出**：**本地报告**（Markdown 为默认、HTML 可选）——返工文件 Top 榜、重复造轮子候选 Top 榜、Read:Edit 比与趋势、每个结论附**证据锚点**（会话 id、事件行号、版本文件名）；
- **确定性纪律**：报告只渲染引擎结果，**零判定逻辑**（与系列惯例一致）；报告为纯本地文件，**不上传、不遥测**。

### 5）真值基准（内置评测，可复现）

- **输入**：**程序化生成**的合成会话日志（假项目名/假文件路径，白名单登记）+ **植入真值**——生成器在造样例时**同步标注**"该文件应判为返工 / 该函数应判为重复"（程序化标注，非人工事后补）；
- **输出**：基准套件 + 指标口径进 README，一条命令复现评测（检测率 / 误报率等口径写进 README，不写会漂移的硬数字）；
- **确定性纪律**：合成会话日志**零真实项目、零真实路径、零真实用户名**（白名单登记见 [data/README.md](../data/README.md)）；生成器与真值植入逻辑入仓可审计；**真值覆盖度门槛**：基准须按异常类型（返工 / 重复造轮子 / 正常）与边界类型分别设置最低覆盖项，口径写进 manifest，防合成真值偏科。**边界类型枚举以 [05-数据计划.md](05-数据计划.md) §4.2 与 `data/synthetic/manifest.json` 的 `coverage.min_count_by_type` 为准**（当前 4 类：版本链缺失 `missing_chain` / 单次编辑 `single_edit` / 恰好卡阈值 `threshold_exact` / 符号名近但不重 `near_miss`；此处不复制各类型最低例数，数值只在 manifest 一处）。

### 6）扩展项（不承诺首期交付）

- **完整 AST / 指纹克隆检测**：跨文件语法树或指纹级克隆检测，工程量大，**首期不做**（见 §六 边界）；
- **跨会话趋势**：多会话聚合的返工/重复趋势（首期只做单会话 + 可选多会话聚合的粗版）；
- **CI 集成**：在 CI 中跑返工/重复指标并对 PR 输出报告（留扩展）。

## 六、边界与非目标

- **不做代码质量全量扫描**：不做 lint / 风格 / bug 扫描（那是既有工具的地盘）；**聚焦 agent 返工与重复**这一交叉点；
- **不修改用户代码**：只读分析（读会话日志、读版本快照、读项目源码做符号提取）；**绝不写回、绝不自动修复**；
- **隐私红线**：会话日志含**代码与 prompt**（敏感）——**纯本地、零上传、零遥测**；不联网、不上报、不收集；报告与中间产物只落本地；文档明确声明"本工具不发送任何数据"；
- **不做"AI 评分"**：指标是**确定性计数**（版本链、Edit 次数、Read:Edit 比、符号名粗匹配），**不是模型 judgement**——不引入任何 LLM/模型打分；
- **首期范围限定**：**MVP 不做完整克隆检测**（AST / 指纹级），只做**基于会话日志的返工检测 + Read:Edit 比 + 同会话内新建函数与项目已有 util 的粗匹配**；完整克隆检测、跨会话趋势、CI 集成留扩展；
- **不承诺跨机器可比**：会话日志格式随 agent 版本演进，解析器须以"本机实测字段"为依据并**自适应发现路径**；格式变化时如实报"不支持/字段未核对"，不得猜测；
- **品牌隔离**：不复制姊妹项目代码；公开文档不提其余项目业务领域。

---

**数值口径**：所有阈值（返工版本数 N、Edit 次数 M、粗匹配相似度）**只在配置一处定义**，报告/基准/文档一律引用该处；**不写会随实现漂移的硬数字**；数据源条数为**本机实测快照**（附基准日），非交付承诺。
